# 数据字典

导入 JSON 对象。必填 `batch` 为原样保留的批次号，`at` 为带偏移的批次记录时刻。下表三组数组都必填，允许空数组。针对每张表从 1 编数据行号。输入文件中的具体记录由表名与数据行号定位。

| 数组 | 关键字段 | 约束 |
|---|---|---|
| `roads` | `road`、`name`、`direction`、`axis`、`length_m`、`from_m`、`to_m`、`team` | 道路编号与方向是责任键。`axis` 为两个本地米制平面坐标 `[x0,y0,x1,y1]`。`+` 由起点向终点，`-` 反向，桩号基准保持相同。责任区间 `[from_m,to_m)`。`team` 可选，为责任班组编号，参与同键冲突判定。 |
| `points` | `vehicle`、`road`、`direction`、`time`、`plow`、`x`、`y` | 以车辆和 UTC 秒去重，同秒矛盾点保留轨迹断点。开关值必须为布尔值，自本点起向下一点生效。 |
| `windows` | `road`、`direction`、`start`、`end` | 偏移必填。半开窗口 `[start,end)` 最长 24 小时。同方向窗口先求并集。 |

另有三组可选数组，用于班组结算；缺省时全部已覆盖区间只列待复核。

| 数组 | 关键字段 | 约束 |
|---|---|---|
| `teams` | `team`、`name`、`rate_per_km` | 班组册。`team` 唯一，同号定义冲突全部隔离。`rate_per_km` 为可选公里单价（元），缺省只计里程不计金额。 |
| `vehicles` | `vehicle`、`team` | 车辆名册。同一车辆归属冲突全部隔离；登记班组册时 `team` 须在其中。 |
| `dispatches` | `dispatch`、`team`、`road`、`direction`、`start`、`end` | 支援单。半开时段 `[start,end)` 最长 24 小时，线路方向须在线路册，同号定义冲突全部隔离。 |

投影采用有限轴线最近点，最大横向偏移 28 米，按测绘全长折算并取最近整数米。窗口裁切后的分数米向内量化。两个有效锚点相隔超过 150 秒时，中间相交的距离作为待核证范围，已有同向覆盖优先采信。窗口缺失归证据不足。漂移或互斥定位截断相邻段，无法定位的距离由其他有效轨迹或窗口决定。`pending` 是有效窗口内未获得覆盖且没有可量化缺证的区间。责任对账只纳入采信的方向定义，冲突线路的原值单独保留。

结算按区间归属裁定：车辆所属班组即路段责任班组为自营；跨班组作业须有时段与方向都匹配的支援单方为支援，结给外援班组。里程按区间并集计量，不按车辆毛里程。车辆未登记名册、线路未登记责任班组、跨班组无支援单、同一区间多班组覆盖的，归属未核清，只列待复核，不计入可结算里程与金额。金额按班组可结算里程乘公里单价精确折算到分。班组册、线路方向与结算里程在同一冻结快照内，结算页以 `versions.registry_sha256` 与凭证摘要核对同版本。同批轨迹重跑或断点续跑按内容寻址复用归档，不重复计价，不改变已核归属；重算失败保留旧版结算单。

`references` 记录车辆、轨迹起止行、裁切时间与窗口行。`issues` 保留来源、原因码和可用的原值。工单凭证为 JSON，含冻结输入、规则版本、运行摘要、汇总、区间证据、分段归属与签收信息。
